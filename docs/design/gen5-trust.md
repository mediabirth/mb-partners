# GEN-5「信用」— 診断オファー・実例・紹介者保護 設計書 v1

- 日付: 2026-08-18 ／ 起案: リード ／ 承認: 勝彦（GEN-5着手指示 2026-08-18・完全自走）
- 位置づけ: GEN 1〜4（機械）の次＝**紹介者が評判を貸せる根拠**をプロダクトに実装する。
  戦略正典: 隣接業パートナー型を主エンジン・診断オファーを弾・相互扶助を潤滑油（2026-08-18 リード提言・勝彦採択）。
- 大原則: 盛らない（実例は同意済みの本物のみ・0件は面ごと不在=GEN-3抑制思想）・money非接触・
  診断は無料の通常起票（報酬計算に新経路を作らない）。

## 1. 設計判断（リード裁定）

1. **紹介の最小単位を「発注」から「診断」に変える**。頼む単位が軽いほど紹介者の評判リスクは小さい。
   診断=無料・成果物が必ず出る・断られても誰も傷つかない、をプロダクトの一級市民にする。
2. **実例（事例）は同意フラグ必須の別テーブル**。同意なしに publish できない構造にする
   （ペルソナの真実をスキーマで強制）。0件の間は顧客面に節ごと出さない。
3. **紹介者保護は両面で明文化**: 顧客面（/r/）には「安心の約束」として、パートナー面（共有シート）には
   「あなたの顔を潰さない3か条」として。同じ構造の裏表を、それぞれの語彙で。
4. **紹介料の存在は顧客面フッターに1行開示する**（ステマ規制/景表法対応・2023年10月〜）。
   従来の「紹介の機構を透けさせない」原則の部分改定＝*見た目の清潔さは維持しつつ、fine printで
   正直に開示*。紹介者を法的に守る意味でも必要（この改定は勝彦へ明示報告事項）。
5. **共同受注率を North Star の隣に置く**。この戦略（紹介者が案件に残る）が効いているかの直接証拠。
6. スコープ外（後続バッチ）: /partners LP の隣接業向け改修・相互扶助（持ち寄り会）のプロダクト化・
   診断の自動レポート生成。

## 2. 仕様

### 2.1 診断オファー（entry_offers）
- migration（additive）: `entry_offers` 新テーブル
  `(id uuid pk, service_id references services, name text, tagline text, deliverable text,
    price_label text default '無料', active boolean default true, sort int, created_at)`。
  money列なし・報酬とは無関係（menus/menu_rewardsに触れない）。
- 初期データ3行（勝彦がconsoleで編集可能・投入はバッチ内seed）:
  - RESONATION「ブランド健康診断」/ ロゴ・サイト・言葉の一貫性を拝見し、現在地を1枚のレポートに
  - PRAGMATION「業務と採用の健康診断」/ 業務の流れと採用の詰まりを伺い、改善の優先順位を1枚に
  - EMANATION「発信力診断」/ いまの発信を拝見し、届いていない理由と次の一手を1枚に
- **/r/ 面**: メニュー一覧の上に診断ブロック（「まずは無料診断から」・成果物説明・所要目安）。
  診断を選んで送信すると通常の相談起票（deals・amount 0・memo先頭に「ご相談内容: {診断名}」＝
  既存のメニュー選択memo方式と同型）。**報酬・凍結・帰属ロジックに新経路を作らない**。
- **共有シート**: 共有対象に「診断カード」を追加（URL `?o={offerId}`・src=card併存）。
  文面テンプレは診断用（「無料で◯◯を診てくれる会社があります」の型・押し売り語なし）。
- **OG画像**: `?o=` 指定時は診断名を主役にしたカード（GEN-2レンダラの入力拡張・許可表は
  entry_offers の name/tagline のみ・money禁止語ガード同適用）。
- console: サービスマスタ（/console/services）に診断オファー節（CRUD・active切替・375px準拠・
  PageGuide追随）。

### 2.2 実例（case_studies）
- migration（additive）: `case_studies` 新テーブル
  `(id uuid pk, service_id references services, title text, client_label text,
    summary text, outcome_label text null, consent_confirmed boolean not null default false,
    published boolean not null default false, sort int, created_at)`。
  - **DB制約で `published=true` は `consent_confirmed=true` を要求**（check制約）＝同意なき掲載を
    スキーマで不可能に。
  - client_label は実名（「株式会社◯◯様」）or 属性表記（「県内の製造業（従業員30名）様」）を
    勝彦が選んで入力。summary/outcome_label は顧客向け語彙のみ・**金額/率のmoney語は
    保存時にサーバ側で拒否**（GEN-1境界assertと同じ正規表現）。
- **/r/ 面**: 「実例」節（published のみ・sort順・最大3件）。0件なら節ごとDOM不在。
- console: サービスマスタに実例節（CRUD・同意チェックボックス・公開切替）。
- 掲載同意の取得自体は勝彦の運用（§5）。

### 2.3 紹介者保護の明文化
- **/r/ 面「安心の約束」ブロック**（フォームの直前・3行・静音）:
  「初回のご相談・診断は無料です」「押し売りは一切しません」「合わないと感じたら、そこで終わりにして
  構いません」。
- **/r/ フッター開示1行**（§1-4）: 「本ページをご紹介いただいた方へ、成約時に紹介料をお支払いする
  ことがあります」。fine print と同じ文字サイズ・トーン。
- **共有シート「あなたの顔を潰さない3か条」**: 「売り込みはこちらが引き受けます」「進み方はいつでも
  あなたに見えます（案件タイムライン）」「合わなければ即終了・ご友人に負担は残しません」。
  常設は1行+ⓘ（静音原則）。

### 2.4 共同受注率（/console/growth・North Star節に1指標追加）
- 定義: **紹介起票 deals のうち、紹介者本人が納品側にも関与した率**。
  関与の判定=①その deal の協力タスク（手動）を紹介者が1件以上完了 ②その deal の委託
  （delivery/assignment）先が紹介者本人 ③deal のサービスのサプライヤーが紹介者本人——のいずれか。
  実装時は既存スキーマの正確なテーブル名で判定式を確定し、統合レポートに全文明記すること。
- 表示: 「共同受注率 X%（n=a/b）」・分母0は「—」。lib/north-star.ts に純関数追加・canon固定。

## 3. 境界・不変
- money 4ハッシュ非接触: entry_offers/case_studies は money 外・診断起票は amount0 の通常経路・
  報酬/凍結/fee/帰属ロジック不変。menus・menu_rewards 不変。
- 公開文言の供給源は entry_offers（name/tagline/deliverable）と case_studies（published行）のみに
  限定した許可表方式＋money禁止語ガード（保存時+表示時の二重）。
- GEN-1〜4 の挙動不変（ダイジェスト・カード・鼓動・North Star既存指標）。
  共有シートの既存機能（メニュー選択・QR・LINE）は不変のまま診断を追加。
- 認証・cookie 非接触。

## 4. 検証（実装バッチ合格条件）
1. 単体（canon）: 診断/実例の抑制（0件不在）・money禁止語ガード（保存拒否・表示縮退）・
   共同受注率の全分岐（判定3種・分母0）・決定性。
2. throwaway E2E: 診断起票→deals通常起票（amount0・reward_snapshot従来同形式）・
   consent なし publish が **DB制約で失敗**すること・共同受注率=独立SQL全桁一致・FK撤去残置0。
3. 本番実測: /r/ 診断ブロック+約束ブロック+フッター開示の実描画・実例0件で節不在・
   OG診断カード200/png・375px溢れ0・pageerror 0・ペルソナの真実（growth数値=psql）。
4. 品質ゲート7項目（console 2節のCRUD含む）・test:verify全green・money 4ハッシュ前後一致・残置ゼロ。

## 5. 運用（勝彦の手番・プロダクト外）
- 初期実績3〜5件の獲得（直接信用・MBHOUSE直営）と**掲載同意の取得**→console から実例登録。
- 隣接業10人リスト（士業・制作/開発フリーランス・コンサル・保険/不動産営業）→高さんモデルで招待。
- 診断3種の文言はseed後にconsoleで自由に磨いてよい（正典はDB・設計書の文言は初期値）。

## 6. GEN-5後の状態＝「何がどう変わるか」
- 紹介者が配るもの: 「発注の相談」→「無料診断の1枚カード」（評判リスクが桁で下がる）
- 顧客が着地して見るもの: メニューの棚→ **診断の入口＋実例＋安心の約束**（信用の根拠が並ぶ）
- 紹介者が確認できるもの: 保護3か条＋案件タイムライン（顔を潰されない構造的保証）
- 勝彦が毎週見るもの: 2回目紹介率の隣に**共同受注率**（隣接業戦略の効き目の直接証拠）
